## 현재 제품 방향

5명·14일 시제품. 관리자 C# WinForms 앱과 사용자 C# WinForms 앱이 하나의 ASP.NET Core 서버에 연결됩니다. 서버는 유선 이더넷의 TCP/IP를 통한 REST/JSON API로 인증, 역할·라인 권한, 검사/문제/조치 처리, EF Core·SQLite 저장, AI 요청 중계와 감사 이력을 담당합니다. 두 클라이언트는 DB에 직접 접근하지 않습니다. HTTP REST는 TCP/IP 위에서 동작하며, 별도 raw TCP 소켓 서버는 요구가 구체화되기 전까지 필수로 간주하지 않습니다.

대표 LINE 1과 품목 1종만 실제 상세 기능을 구현합니다. LINE 2~4는 가상 대시보드 데이터로 표시하고 실제 통계에 섞지 않습니다. 검사는 장서진의 OpenCvSharp 일반 영상처리로 형태·윤곽 및 색상 두 기준만 사용합니다. 세 결과는 **정상 / 불량 / 판정 불가**입니다. 품목 불량, 생산라인 문제, 검사 시스템 문제는 서로 다른 ID와 처리 규칙을 갖습니다. 카메라·영상·프로그램 오류는 판정 불가 및 검사 시스템 문제로 이어지며 정상이나 불량으로 임의 저장하지 않습니다.

공도현의 상담 AI는 생산라인 또는 검사 시스템 문제가 생긴 뒤 매뉴얼/점검표 근거로 원인 후보와 점검 순서를 안내합니다. 품목 검사를 수행하거나 검사 결과를 바꾸지 않습니다. 설비 정지·재가동·인터록 해제, 문제 완료·종결도 실행하지 않습니다. AI 실패·근거 없음 상황에도 매뉴얼/점검표와 관리자 문의가 동작해야 합니다. AI 대화, 관리자 대화, 시스템 메시지는 유형과 기록을 구분합니다.

문제 업무 흐름은 **발생 → 사용자 확인 → 조치 중 → 완료 요청 → 관리자 확인 → 종결**입니다. 관리자는 반려하고 추가 조치를 요구할 수 있습니다. 사용자의 완료 요청과 관리자의 최종 종결은 서로 다른 단계이며 서버에서 권한과 전이를 검증해야 합니다.

## 김하균의 확정 담당 범위

사용자가 직접 명시한 목록을 기준으로 합니다.

- ASP.NET Core REST API와 유선 이더넷 TCP/IP 통신.
- 관리자·사용자 로그인 인증과 역할·라인 접근 권한 검사.
- 사용자 정보와 검사 결과 저장.
- 문제 상태, 상태 변경, 조치 기록 저장.
- 관리자 문의 전달과 AI 상담 요청 중계.
- 기존 JSON **영속 저장소**를 EF Core·SQLite로 교체. API의 JSON 요청/응답은 유지할 수 있습니다. 현재 저장소에는 아직 해당 JSON 구현이 보이지 않으므로 교체 시 실제 소스를 먼저 확인하세요.
- API 요청·응답 형식과 공용 DTO/오류 형식 관리.
- Git 최종 병합과 전체 실행 관리. 이는 역할 배정이며 아직 병합이나 실행이 완료됐다는 뜻이 아닙니다.

이 책임에 포함되는 서버 측 세부 규칙:

- 계정 ID 고유성/재사용 금지, 비밀번호 해시, 비활성화·재활성화, 허용 라인 변경. 비활성화 후 로그인과 후속 요청 차단, 과거 기록 보존. 사용자 ID와 기록 당시 표시명 보존.
- 매 요청 계정 활성 여부·역할·허용 라인·기능 권한 확인. 관리자 API 직접 호출이나 다른 라인 ID 요청도 거부. 권한 거부는 계정/기능/라인/시각 로그로 남기되 비밀번호·토큰은 기록하지 않음.
- 영상처리 결과의 검사/품목 ID, 이미지 참조, 형태·윤곽/색상별 결과, 최종 세 결과, 적용 검사 기준 버전, 시각과 오류/사유 저장. 검사 기준은 관리자만 변경하고 새 버전·변경 사유·전후 값·관리자·시각을 기록. 과거 검사는 당시 버전을 유지.
- 품목 불량과 라인/검사 시스템 문제 분리. 같은 라인·유형의 미종결 문제는 중복 생성하지 않고 발생 횟수/상태 갱신. 문제 당시 라인/카메라/센서/검사 프로그램 상태·오류·마지막 정상 시각 보존.
- 문제 전환마다 이전/이후 상태, 수행 계정·역할·담당 라인, 시각, 조치·반려 사유, 당시 상태 기록. 종결 이력을 덮어쓰지 않음.
- AI에는 문제 맥락을 전달하고 질문/답변/모델/문서명·버전·절/오류를 저장. 관리자 문의에는 문제/현장 상태·AI 요약 또는 근거 없음·사용자 조치·관련 이미지 맥락을 전달. AI가 검사·종결 권한을 갖지 않도록 서버에서 제한.
- 실제/가상 통계를 구분. 불량률은 `불량 / (정상 + 불량) × 100`, 판정 불가는 분모 제외. 문제 수는 상태 변경 횟수가 아닌 고유 문제 ID 수. 0건일 때 표현은 API/UI 계약에서 정해야 함.
- 재연결 시 상태/이력 복구, 중복 요청 시 중복 검사·문제·알림 방지, 두 앱이 같은 대표 라인 데이터를 보는지 통합 검증.

## 필수 검증·시연 흐름

v5 핵심 검수는 다음 일곱 가지입니다. 일반 사용자의 관리자 API 차단, 형태/색상 검사 반복성, 영상 실패의 판정 불가 처리, 세 사건 유형과 상태 이력 분리, AI의 검사 결과 변경 금지, AI 장애 시 문서/관리자 문의 유지, 사용자 완료 요청과 관리자 종결 구분.

7분 시연은 관리자 로그인·대시보드·가상 배지 → 사용자 등록/LINE 1 권한·관리자 접근 거부 → 정상/불량 검사·분리·기록 → 카메라 실패·판정 불가·검사 시스템 문제 → 매뉴얼/상담 근거 → 근거 부족 시 관리자 문의/지시 → 사용자 조치/완료 요청·관리자 종결 → 검사/문제/상담/문의/권한/기준 감사 이력 순서입니다. 두 PC 전체 실행이 최종 목표입니다.

14일 계획은 D01~02 솔루션/DTO·IP/포트·검사/문제/권한/API 규격, D03~04 두 앱/서버/DB/로그인·권한, D05~06 검사 저장, D07~08 문제·상태·알림·문서, D09~10 AI·문의·종결·감사, D11~12 기록·통계·권한/장애/재연결/중복 요청 검수, D13~14 실행본 고정·두 PC 리허설·발표입니다. 일정이 밀리면 가상 애니메이션과 부가 통계를 줄이고 핵심 인증·검사·문제 처리·상담/문의·감사는 유지합니다.

## 결정이 필요한 값과 버전 차이

v5에서 아직 정하지 않은 사항: 대표 품목과 정상/불량 영상, 카메라/조명/촬영 조건, 윤곽 비교·임계값/색상 공간·범위/판정 불가 기준, .NET 버전·서버 IP/포트, 구체 인증 방식, 문제 시나리오 3~5개·매뉴얼/점검표 작성 책임, AI 모델/API 예산, 원본 이미지/대화 보존 기간. 사용자가 EF Core·SQLite를 담당 기준으로 추가 확정했습니다. 관리자 반려 전이·검사 수에 판정 불가를 포함하는 표현·0건 통계·재검사 정책·실시간 전달 방식도 인터페이스 작성 시 명확히 해야 합니다.

v2는 C++ MFC 작업자 앱, AI 이미지 검사, 상세 LINE 3, 정상 후보/불량 의심/검토 필요, ONNX/Python 추론, SQLite와 일반 WebSocket 제안을 포함했습니다. **현재 기준 v5는 양쪽 WinForms, 일반 영상처리, 상세 LINE 1, 정상/불량/판정 불가입니다.** v2의 온도 70/80℃, 정체 10초, 통신 6초, AI 정확도·응답 목표 같은 데모 수치를 현재 확정 기준으로 옮기지 마세요. 별도 5팀 사례의 Flask·MFC·MySQL·바코드·컨베이어·채팅 코드는 현행 기능 요구로 받아들이지 마세요.

## 2. 앱에 넣는 방법 (검출만 할 때)

**필요한 파일은 `models/best.onnx` 하나입니다.** 사진·라벨·`dataset`은 필요 없습니다.

### ONNX 입력·출력 (실제 파일에서 확인한 값)

| | 이름 | 모양 | 내용 |
|---|---|---|---|
| 입력 | `images` | `[1, 3, 640, 640]` float32 | RGB, 0~1로 나눈 값, NCHW |
| 출력 | `output0` | **`[1, 9, 8400]`** | 후보 8400개 × (박스 4 + 클래스 점수 5) |

- 출력 9줄 = `cx, cy, w, h` (640×640 입력 기준 픽셀) + 클래스 0~4의 점수(이미 0~1 확률).
- **NMS는 앱에서 해야 합니다** (end2end 아님). 보통 신뢰도 0.25 이상, IoU 0.45~0.7로 NMS.
- 전처리: 원본을 비율 유지로 640에 맞추고 남는 곳을 회색(114)으로 채우는 **letterbox**가 Ultralytics 기본입니다. 박스를 원본 좌표로 돌릴 때 이 비율·여백을 되돌려야 합니다.
- 확인: 같은 사진을 `best.pt`와 `best.onnx`(ONNX Runtime, CPU)로 돌려 같은 결과(클래스·신뢰도 0.91/0.86~0.87)를 확인했습니다.

### ⚠️ 이전 모델과 다른 점 (앱 코드에서 꼭 확인)

1. **출력 줄 수가 8 → 9로 바뀜.** 지금까지 조장 툴로 만든 모델들은 클래스가 4개(`target_iphone, other_phone, crack, <폰 이름>`)라 출력이 `[1, 8, 8400]`이었습니다. 이 모델은 클래스 5개라 `[1, 9, 8400]`입니다. 코드에 `8`이나 `4 + 4`가 박혀 있으면 고쳐야 합니다. `4 + 클래스 수`로 계산하게 바꾸는 게 안전합니다.
2. **클래스 번호가 바뀜.** 이전 모델들은 모두 자기 폰이 **3번**이었습니다. 이 모델은 0~4번이고, `target_iphone / other_phone / crack` 클래스는 **없습니다.**
3. **앱이 모르는 이름.** 조장 `04_Vision` 검사 코드는 `crack`, `crack_phone`, `iphone_12_pro_max_Crack` 같은 정해진 이름만 알아듣는다고 기록되어 있습니다(`with-claude-yolo-training/README.md`). 위 5개 이름을 판정 규칙에 추가해야 합니다. 예: 0번이면 불량, 1~4번이면 해당 기종 정상.

### 속도

- 이 PC 그래픽카드(GPU)로 사진 1장에 약 1.7ms (전처리 제외). 모델은 가장 작은 `n` 크기라서 더 작게 할 여지는 거의 없습니다.
- 앱에서 프레임이 끊기면 모델보다 **ONNX를 CPU로 돌리는지**, **매 프레임 검사하는지**, **화면 그리기와 같은 스레드인지**를 먼저 확인하세요. 해결 방법: GPU 실행(DirectML/CUDA), 몇 프레임마다 1번 검사, 검사를 별도 스레드로.

## 3. 라벨 기준 (사진 1장에 박스 2개)

모든 박스는 그 폰의 클래스 번호로 그려져 있습니다. 박스 종류는 이름으로 나뉘지 않습니다.

| 클래스 | 큰 박스 | 작은 박스 |
|---|---|---|
| 기종 4개 (1~4) | 휴대폰 뒷면 전체 | **카메라 모듈** (뒷면 면적의 약 7~15%) |
| `crack_iphone` (0) | 휴대폰 뒷면 전체 | **깨진 부위** (여러 군데면 여러 개, 면적 14~92%) |

- 그래서 한 폰에서 **같은 이름의 박스가 2개** 나오는 게 정상입니다. 앱에서는 가장 큰 박스를 "폰 위치"로 쓰고, 0번(`crack_iphone`)이 하나라도 나오면 불량으로 보는 식으로 정하면 됩니다.
- 기종 쪽 작은 박스가 카메라 모듈이라는 건 사진에 박스를 그려 보고 판단한 것입니다. 라벨을 그린 조원에게 한 번 확인하세요.

## 6. 다시 학습하는 방법

`dataset/` 폴더는 `images/`를 복사한 것이라 GitHub에는 올리지 않았습니다(`.gitignore`). 아래 스크립트로 똑같이 다시 만들 수 있습니다.

```powershell
cd all_phones
py -3.13 make_dataset.py          # dataset/ 생성 (클래스마다 20% 검증, 이번 학습과 같은 분할)
py -3.13 ..\with-claude-yolo-training\06_TrainingTool\ProductionLine.TrainingTool\train_yolo.py `
    --data dataset\data.yaml --model yolo26n.pt --epochs 300 --imgsz 640 --device 0 --output models_new
```

- `make_dataset.py`로 만든 분할이 이번 학습에 쓴 분할과 **파일까지 같은 것**을 확인했습니다.
- 결과는 `models_new/`에 생깁니다. 기존 `models/`를 덮어쓰지 않게 다른 이름을 쓰세요.
- 이 PC 기준 300회에 약 1시간 50분 걸렸습니다.
- 조장 학습 툴(`06_TrainingTool`)로 이 폴더를 **프로젝트 열기**로 열어도 됩니다. 단, 툴의 **학습 데이터 만들기**는 클래스 구분 없이 전체 20%를 검증으로 떼므로 분할이 조금 달라집니다.

### 사진·기종 추가

1. 새 기종은 `classes.txt` **맨 아래에 한 줄 추가**합니다(5번). 위 순서는 바꾸지 마세요.
2. 사진은 `images/`, 라벨은 `labels/`에 같은 이름(`.txt`)으로 넣습니다. 라벨 첫 숫자를 새 번호로 쓰세요.
3. 다른 조원 폴더를 합칠 때는 그 폴더의 `classes.txt`를 보고 번호를 바꿔야 합니다(그 폴더들은 보통 자기 폰이 3번).
4. `make_dataset.py` → 학습.

### 점수를 더 올리려면 (효과 큰 순)

1. 실제 컨베이어 카메라 사진 추가 (기종마다 50~100장, 위치·방향·조명 다르게)
2. 라벨 박스를 폰 외곽에 딱 맞게, 같은 기준으로 (깨진 아이폰 박스 1개짜리 약 50장 고치기)
3. 정상 폰·빈 벨트 사진을 빈 라벨로 추가
4. 이미지 크기 800 (박스 정밀도↑, 속도↓). 더 큰 모델(`yolo26s`)은 앱 프레임이 이미 끊긴다고 해서 보류

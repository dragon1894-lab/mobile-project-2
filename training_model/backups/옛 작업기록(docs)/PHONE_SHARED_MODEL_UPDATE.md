# 휴대폰 YOLO 공유용 모델 업데이트

이 문서는 이전 `phone` 모델의 적용 기록입니다. 현재 기본 모델과 모델 선택 방법은 [최신 통합 안내](PHONE_PACKAGE_MERGE.md)를 참고하세요.

적용 파일: `휴대폰_YOLO_CSharp_공유용.zip`

- 프로젝트 모델: `04_Vision/models/best.onnx`
- 입력: float32 `[1,3,416,416]`, 중앙 letterbox 회색 114, RGB/255, NCHW
- 출력: `[1,5,3549]`, 중심 x/y·너비·높이·phone 신뢰도, 별도 objectness 없음
- 기준: 신뢰도 0.5, NMS IoU 0.45
- 현재 샘플: C#에서 phone 신뢰도 87.4%로 검출. 이 값은 전체 정확도가 아님

압축 파일 안 모델의 수정 시각이 기존 실행 모델보다 과거인 경우에도 교체되도록 ONNX 출력 복사 설정을 `Always`로 바꿨습니다. 배포된 파일과 원본 압축 모델의 SHA-256도 대조합니다.

## 가능한 기능

휴대폰 박스·신뢰도 표시, 0.1초 목표 간격의 연속 검출, 같은 물체 중복 집계 방지, 검출 시 아두이노 벨트 정지 명령을 지원합니다. 물리적 모터 동작은 이번 모델 업데이트 테스트에서 실행하지 않습니다.

현재 모델은 휴대폰 위치 검출 전용으로 아이폰 기종·다른 기종 구분, 색상, 깨짐 판정을 하지 않습니다. 화면에는 `휴대폰 검출 완료 · 품질 판정 미지원`으로 표시하고, 서버에는 판정 불가와 실제 검출 신뢰도를 기록합니다. 정상·불량 개수는 늘리지 않습니다. 형태·색상 값은 미측정이므로 `—`로 표시합니다.

기존 3클래스 모델도 ONNX 메타데이터에서 읽어 사용할 수 있습니다. 이전 모델·소스 백업은 `output/backups/before-shared-phone-model-20261017-113137.zip`에 보관했습니다. `best.pt`가 없는 공유용 패키지이므로 예전 학습 체크포인트가 현재 ONNX와 같은 모델인 것처럼 배포하지 않습니다. 원래 학습 프로젝트의 최상위 `models`는 그대로 보존했습니다.

## 적용 실행

1. 서버·사용자·관리자·학습 도구를 종료합니다. 실행 중인 파일은 Windows가 잠가 교체할 수 있습니다.
2. `ProductionLineSystem.sln`을 다시 빌드합니다.
3. 서버를 먼저 실행하고 사용자·관리자 앱을 실행합니다.
4. 카메라 연결 → YOLO 모델 확인 → 검사 시작을 누릅니다.
5. 벨트 연동은 기존 COM 연결 절차를 사용합니다. 이번 모델 변경만으로 아두이노 코드를 다시 업로드할 필요는 없습니다.

카메라 결과용 API `/api/inspections/camera`는 품질 판정 가능 여부를 별도로 전달합니다. 분류 기능이 없는 모델은 클라이언트가 정상 값을 보내더라도 서버가 판정 불가로 저장합니다. 기존 점수 시뮬레이션 API와 과거 기록 형식은 유지됩니다. 새 API가 없는 예전 서버를 사용하면 저장 오류가 나므로 서버도 함께 업데이트해야 합니다.

원본 제공 안내에 따르면 1장의 사진을 변형한 100장으로 학습한 시연 모델입니다. 컨베이어 촬영 조건에서의 검출 성능은 별도로 확인해야 합니다.

# 보고서 정리 (report_from)

2026-10-23 김하균 정리. 생산 검사 보고서를 어떻게 만들지 정한 내용과 예시 파일입니다.
**보고서 기능은 아직 만들지 않았습니다.** 이 문서는 정한 내용을 학습 컴퓨터 쪽과 같이 보려고 올립니다.

## 파일

| 파일 | 내용 |
|---|---|
| `보고서_예시.csv` | 예시 보고서 (가짜 데이터). 엑셀로 열면 됨 (UTF-8 BOM) |
| `보고서_예시_미리보기.png` | 위 CSV를 엑셀로 열었을 때 모습 |

## 정한 것

1. **제목:** `1번 라인 - 생산 검사 보고서` (우리는 1번 라인만 실제로 검사)
2. **형식:** CSV 파일. 그래프는 넣지 않고 표로만 만듦
3. **맨 위:** 검사 기간(언제부터 언제까지), 작성자, 작성 시각
4. **실시간:** 보고서를 만드는 그 순간까지의 최신 DB 데이터로 만듦
5. **기종을 알아내지 못한 검사(기종 미확인)는 기종별 분석에 넣지 않음.** 미확인인데 정상·불량이 있는 건 말이 안 되므로 판정 불가로만 셈
6. **긴급 정지 버튼**은 센서가 아니라 **이벤트 기록**에 넣음
7. **센서**는 최고값만이 아니라 시간에 따라 계속 보이게 함 → CSV라서 **시간대별 표**(예시는 1시간 단위, 평균·최고)

## 보고서 칸과 DB 위치

| 칸 | 내용 | DB 표 |
|---|---|---|
| 1. 검사 요약 | 총 검사, 정상, 불량, 판정 불가, 불량률 | `Inspections` |
| 2. 기종별 분석 | 기종, 검사, 정상, 불량, 불량률 | `Inspections.PhoneModel` |
| 3. 센서 기록 | 시간대별 평균·최고 온도, 습도, 가스(MQ-9 A0) | `LineHardwareLogs` (10초마다, 7일 보관) |
| 4. 문제·조치 | 등록 시각, 문제, 상태, 종결 시각 | `Issues`, `IssueHistories` |
| 5. 검사 이력 | 검사 시각, 판정, 기종, 신뢰도 | `Inspections` |
| 6. 이벤트 기록 | 벨트 구동·정지, 긴급 정지 작동·해제, 문제 등록·종결 | `LineHardwareLogs`(상태 변경), `IssueHistories` |

불량률 = 불량 ÷ (정상 + 불량) × 100 (판정 불가는 빼고 계산, 관리자 앱과 같은 기준)

## 학습 컴퓨터에 알릴 것 — YOLO 클래스 이름

- 불량(깨진 휴대폰)은 `crack iphone`처럼 나오면 안 되고 **`기종_crack`** 형식으로 나와야 함
  - 예: `iphone_12_pro_crack`, `iphone_13_crack`
  - 정상은 `iphone_12_pro`, `iphone_13`처럼 기종 이름만
  - 전부 소문자, 띄어쓰기 대신 `_`
- 이 이름 그대로 DB의 기종 칸(`PhoneModel`)과 보고서에 들어감
- 이름 규칙에 맞춰 **다시 학습할 예정**

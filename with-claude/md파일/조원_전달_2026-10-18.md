## 새로 생긴 함수

| 함수 | 하는 일 |
|---|---|
| `UpdateUserAsync(아이디, UpdateUserRequest)` | 사용자 이름·활성 여부·허용 라인·비밀번호 변경 (관리자만) |
| `SendIssueMessageAsync(문제번호, 내용)` | 문제에 문의·답변 메시지 보내기 |
| `GetIssueMessagesAsync(문제번호)` | 그 문제의 메시지 전체 읽기 (보낸 순서대로) |
| `GetIssueMessagesAsync(문제번호, 마지막메시지번호)` | 그 번호 다음의 **새 메시지만** 읽기 |

메시지 규칙

- 1~2,000자. 앞뒤 공백은 서버가 지웁니다.
- 자기 라인의 문제에만 보내고 읽을 수 있습니다.
- **종결된 문제에는 보낼 수 없고, 읽기만 됩니다.**
- 보낸 사람은 로그인한 계정으로 서버가 정합니다. 앱에서 보낼 필요 없습니다.
- **새 메시지 확인은 5초마다** 합니다. 앱이 5초마다 `GetIssueMessagesAsync(문제번호, 마지막메시지번호)`를 불러 새 것만 받습니다. 새 것만 받기 때문에 서버 부담이 적습니다.

오류가 나면 함수가 서버 메시지를 예외로 올려 줍니다. 메시지를 그대로 화면에 보여 주면 됩니다.

| 코드 | 뜻 | 앱에서 할 일 |
|---|---|---|
| 401 | 로그인 필요 (만료·비활성화) | 로그인 화면으로 |
| 403 | 권한 없음 | 메시지 표시 |
| 400 | 입력 오류 (빈 메시지, 2,000자 초과 등) | 메시지 표시 |
| 404 | 문제를 찾을 수 없음 | 목록 새로고침 |
| 409 | 종결된 문제, 순서가 맞지 않는 상태 변경 | 메시지 표시 |

## 조영준 (관리자 앱)

1. **사용자 수정·비활성화 화면**

   ```csharp
   await api.UpdateUserAsync(id, new UpdateUserRequest(이름, 활성여부, 허용라인목록, 새비밀번호또는null));
   ```

   비활성화하면 그 작업자는 바로 로그인이 막힙니다.

2. **문의 확인과 답변**
   - 문제를 고르면 `GetIssueMessagesAsync(문제번호)`로 전체를 읽어 보여 줍니다.
   - **5초마다** `GetIssueMessagesAsync(문제번호, 마지막메시지번호)`로 새 메시지만 받아 아래에 붙입니다. (WinForms `Timer`의 `Interval = 5000`)
   - 답변은 `SendIssueMessageAsync(문제번호, 내용)`.

3. **문제 종결 버튼**: 상태가 "완료 요청"인 문제만 종결할 수 있습니다. 반려할 때는 사유가 꼭 필요합니다.

## 장서진 (사용자 앱)

1. **"확인" 버튼 추가** (이미 요청드린 것)
   서버는 `발생 → 확인 → 조치 중 → 완료 요청`을 한 단계씩만 받습니다.
   "확인"이 없으면 새 문제에서 "점검 시작"이 거절됩니다.

2. **"관리자 문의 등록" 버튼 바꾸기**
   지금은 누르면 **새 문제를 하나 더 만듭니다.**
   **선택한 문제에 `SendIssueMessageAsync(문제번호, 내용)`으로 메시지를 보내는 방식**으로 바꿔 주세요.

3. **관리자 답변 보여 주기**: 관리자 앱과 같은 방식으로 **5초마다** 새 메시지를 읽어 표시합니다. 지금 화면 전체를 새로 고치는 타이머(10초)와는 따로, 메시지용 타이머(`Interval = 5000`)를 두면 됩니다.

4. 종결된 문제에서는 보내기 버튼을 막아 두면 좋습니다.

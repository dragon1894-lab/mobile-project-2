# DB에 저장할 내용

서버가 SQLite 데이터베이스에 저장할 정보입니다. 지금 `store.json`에 들어 있는 내용과 같은 정보를 표(테이블)로 나눈 것입니다.
관리자 앱·사용자 앱은 DB에 직접 접근하지 않고 **서버를 통해서만** 사용합니다.

> 이 문서는 제안입니다. 표 이름과 칸 이름은 만들면서 바뀔 수 있습니다.

---

## 1. 사용자 (누가 로그인할 수 있나)

| 저장할 것 | 설명 |
|---|---|
| 아이디 | 로그인에 쓰는 이름. 중복 불가 |
| 이름 | 화면에 보여 줄 이름 |
| 관리자/작업자 구분 | 관리자(Admin) 또는 작업자(User) |
| 비밀번호(암호화된 것) | 비밀번호 원문은 저장하지 않음 |
| 사용 가능 여부 | 꺼 두면 로그인 불가. 계정을 지우지 않고 막을 때 사용 |

## 2. 사용자별 허용 라인 (이 사람이 어느 라인을 볼 수 있나)

| 저장할 것 | 설명 |
|---|---|
| 아이디 | 어떤 사용자인지 (1번 표와 연결) |
| 라인 번호 | 볼 수 있는 라인 (3번 표와 연결) |

한 사람이 라인을 여러 개 볼 수 있어서 따로 표를 만듭니다.

## 3. 라인 (생산라인 1~4번)

| 저장할 것 | 설명 |
|---|---|
| 번호 | 1~4 |
| 이름 | 예: LINE 1 · 대표 라인 |
| 실제인지 가상인지 | LINE 1만 실제, 나머지는 가상 데이터 |
| 가동 상태 | 예: 가동, 공정 정지 |
| 검사 상태 | 예: 검사 중, 검사 확인 필요 |
| 정상 개수 | 누적 |
| 불량 개수 | 누적 |
| 판정 불가 개수 | 누적 |
| 마지막 갱신 시각 | |

## 4. 검사 결과 (카메라로 검사한 기록)

| 저장할 것 | 설명 |
|---|---|
| 검사 번호 | 검사 한 건마다 고유한 번호 |
| 어느 라인 | 3번 표와 연결 |
| 결과 | 정상 / 불량 / 판정 불가 |
| 형태 점수 | 형태·윤곽 검사 점수 (0~1) |
| 색상 점수 | 색상 검사 점수 (0~1) |
| 이유 | 왜 그렇게 판정했는지 |
| 시각 | 검사한 시각 |

## 5. 문제 (라인에서 생긴 문제)

| 저장할 것 | 설명 |
|---|---|
| 문제 번호 | 문제 한 건마다 고유한 번호 |
| 어느 라인 | 3번 표와 연결 |
| 종류 | 생산라인 문제 / 검사 시스템 문제 |
| 제목 | |
| 설명 | |
| 현재 상태 | 발생 → 확인 → 조치 중 → 완료 요청 → 종결 |
| 등록한 사람 | 1번 표의 아이디 |
| 조치 메모 | 마지막으로 남긴 조치 내용 |
| 생긴 시각 | |
| 바뀐 시각 | 마지막으로 상태가 바뀐 시각 |

## 6. 문제 상태 변경 기록 (누가 언제 상태를 바꿨나)

| 저장할 것 | 설명 |
|---|---|
| 문제 번호 | 5번 표와 연결 |
| 이전 상태 | |
| 바뀐 상태 | |
| 바꾼 사람 | 1번 표의 아이디 |
| 시각 | |
| 조치·사유 | 조치 내용 또는 반려 사유 |

지금은 문제의 **현재 상태만** 남고 "누가 언제 바꿨는지"는 사라집니다. 기획서에서 기록을 남기라고 한 부분이라 따로 표를 만듭니다.

---

## 표 사이의 연결

- 사용자 ↔ 허용 라인 ↔ 라인: 작업자가 어느 라인을 볼 수 있는지
- 라인 → 검사 결과: 한 라인에 검사 결과가 여러 개
- 라인 → 문제 → 상태 변경 기록: 한 문제에 상태 변경이 여러 번

## 나중에 추가할 것

- 관리자 문의·답변 (같은 문제에 대한 사람 간 대화)
- AI 상담 질문·답변 (근거 포함)
- 센서·장치 값 (아두이노를 쓰게 되면)
